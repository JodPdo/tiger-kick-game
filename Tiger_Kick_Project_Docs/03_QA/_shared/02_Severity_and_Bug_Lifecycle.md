# Severity & Bug Lifecycle

## 1. ระดับความรุนแรง (Severity)
| ระดับ | ชื่อ | ตัวอย่าง | การจัดการ |
|---|---|---|---|
| **S0** | Crash | เกมค้าง/ปิดตัวเอง, server ล่ม | บล็อก Exit Gate ทันที ต้องแก้ก่อน |
| **S1** | Desync | เสือซ้อน/หาย, สถานะไม่ตรงกันข้ามเครื่อง | บล็อก Exit Gate ต้องแก้ก่อน |
| **S2** | Gameplay | เตะไม่โดน, cooldown ผิด, จับพลาด | ควรแก้ก่อนปิดเฟส |
| **S3** | UI | ข้อความผิด, ปุ่มเพี้ยน, layout เพี้ยน | แก้ได้ในเฟสถัดไปถ้าจำเป็น |
| **S4** | Cosmetic | เอฟเฟกต์เล็กน้อย, สีไม่ตรง | backlog |

**กติกา Exit Gate**: ห้ามมีบั๊ก **S0 หรือ S1 ค้าง** ก่อนขึ้นเฟสถัดไป

## 2. Bug Lifecycle (วงจรบั๊ก)
```
New
 ↓
Triaged        (จัดระดับ severity + priority)
 ↓
Assigned
 ↓
In Progress
 ↓
Fixed
 ↓
Ready for QA
 ↓
Verified       (QA ยืนยันว่าแก้จริง + ไม่ทำของอื่นพัง)
 ↓
Closed
```
- ทุกบั๊กต้องผ่าน **Verified** โดย QA ก่อน Closed
- ถ้า QA ทดสอบแล้วยังพบปัญหา → ตีกลับเป็น **Assigned** พร้อมหมายเหตุ

## 3. Priority (แยกจาก Severity)
Severity = ความรุนแรงทางเทคนิค, Priority = ความเร่งด่วนทางธุรกิจ/เฟส
บั๊ก S3 อาจ Priority สูงได้ถ้าอยู่บนเส้นทางที่ผู้เล่นเจอบ่อย
